# Lesson 04 — 为什么 BF16 经常是第一个低精度选择

> **谜题：**FP16 并且 BF16 两者都使用16比特。为什么它们的数值行为会如此不同？

[← 第 01 章](../README.md) · [项目主页](../../../README_ZH.md) · [执行的笔记本](../../../chapters/01-mixed-precision-int4/04-bf16-first/lab.ipynb) · [RTX 5090 结果](../../../chapters/01-mixed-precision-int4/04-bf16-first/artifacts/rtx5090-result.json)

## 为什么这个谜题重要

FP16 和 BF16 消耗相同的两个字节，但它们使用这些位的方式不同。BF16 继承了 FP32 的八位指数，并牺牲了分数精度；FP16 保留了较长的分数，但只使用了五位指数。这种交易改变了溢出发生的位置以及累积的舍入误差量，因此仅从字节数量无法做出格式选择。

## 阅读结果前，先做出预测

1. 预测哪个16位格式可以表示`1e5`而无需Inf，哪个格式产生的 GEMM 误差较低。
2. 预测等量存储是否意味着等量 GEMM 延迟。
3. 决定哪个指标会使你选择 FP16，尽管 BF16 的范围更广。

## 1. 从具体的张量和状态开始

FP16 和 BF16 都占用 16 位，但 FP16 使用 5 指数位和 10 小数位，而 BF16 使用 8 指数位和 7 小数位。前者提供更精细的局部间距；后者提供更大的动态范围。

### 三个推理锚点

| # | 本课需要牢记的判断 |
|---:|---|
| 1 | BF16 保留了一个八位的指数，因此其范围类似于 FP32，但其分数部分较短。 |
| 2 | FP16 有更多的分数位，但指数范围要小得多。 |
| 3 | 稳定的dtype并不自动是最快速的dtype；测量实际的工作负载。 |

## 2. 推导机制

舍入误差由值附近的可表示间距决定，而溢出则由指数范围决定。累积策略添加了一个第三个变量：低精度输入可能仍然累积到更宽的dtype，这取决于操作符。

规范化二进制浮点数值的形式为 `(-1)^s × 2^e × (1.f)`。指数位决定动态范围；小数位决定固定指数时相邻可表示数值之间的间距。BF16 的范围接近 FP32，但其存储的七个小数位使得单位舍入误差远大于 FP16 的十个小数位。在点积运算中，输入在乘法前进行舍入，部分和可能使用更宽的累加器，因此输入格式和累加格式必须分别命名。

这预测了一个三方交易：BF16 应该能够承受较大的幅度，FP16 应该经常更准确地重建普通范围的值，而 16 格式可能使用比 FP32 更快的矩阵路径。基准测试独立地测试每个轴，而不是将它们合并为一个获胜者。

## 3. 把理论转化为实验**实验：**比较范围、矩阵乘法误差，和 CUDAFP32的时序，FP16, 和 BF16.

| 实验角色 | 固定定义 |
|---|---|
| 基准 | FP32 GEMM 和 FP32 参考输出 |

| 证据标签 | `pytorch-gpu` |

实验室将大值表示能力、GEMM 误差和 GEMM 延迟分为三个观察点，以便不互相替代。

### 代码导读

探测范围将 `1e5` 转换为 16 位格式并记录有限性。GEMM 探测使用相同的逻辑矩阵，评估输出误差与 FP32 的对比，并对每条路径使用十二个热身后的 CUDA 事件样本进行计时。将误差和计时记录放在一起，可以防止一条快速但数值上无效的路径看起来成功。

因为张量是随机的，且形状为一个正方形 GEMM，结果是一种格式示例而非通用的训练建议。实际网络可以通过归一化、softmax、优化器状态和长归约来放大舍入误差。

## 4. 解读仓库内的 RTX 5090 实测结果

**录制环境：**NVIDIA GeForce RTX 5090 计算能力12.0; PyTorch 2.12.0; CUDA 运行时13.0.

| 实测字段 | 已提交值 |
|---|---:|
| FP16 代表 1e5。 | 否 |
| BF16 代表 1e5。 | 是的 |
| FP16 RMSE | 0.014106 |
| BF16 RMSE | 0.112772 |
| FP16 中位数 | 0.044608 ms |
| BF16 中位数 | 0.044160 ms |
| FP32 中位数 | 0.133376 ms |

### 这些数字说明了什么

BF16 代表了`1e5`，而 FP16 超出了范围；记录的最大有限值大约为`3.39e38` 和`65504`。在普通范围的 GEMM 中，FP16 的 RMSE（0.014106）低于 BF16（0.112772），这与格式布局预测的位数交换完全一致。中位延迟几乎相同——0.044608 ms 对于 FP16 和0.044160 ms 对于 BF16，而FP32 需要0.133376 ms。

证据支持 BF16 作为广泛工作负载的稳定性首选，而不是在每个字段中都作为准确性和速度的优胜者。对于这种输入分布，FP16 保持了更高的精确度，并且在测量范围内保持了同等的速度。

## 5. 解答谜题并做出决策

> BF16 是一个实用的以稳定性为首要基准的基准测试，但在支持的硬件上，工作负载特定的错误和速度仍需测量。

### 验收与回滚门槛

测试范围探测和工作负载输出错误，然后在FP32上测量目标形状的延迟。只有当稳定性和性能达到冻结阈值时，才保留 BF16。

### 这个结论可能如何失效

仅因为 BF16 没有溢出就选择它可能会隐藏不可接受的舍入误差；仅因为 FP16 的 RMSE 更低就选择它可能会在激活值超过其范围时立即失败。另一种失败是假设累加器与输入dtype相同。在精度重要的情况下记录自动混合精度策略和操作行为。
